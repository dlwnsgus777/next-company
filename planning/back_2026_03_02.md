# 백엔드 개발 체크리스트

> 작성일: 2026-03-02
> 기준 기획: planning_2026_03_01.md (칸반 보드 컬럼 커스터마이징)

---

## 배경 및 현황

- 프론트 기획(front_2026_03_01.md)의 칸반 컬럼 커스터마이징은 **localStorage(Zustand persist) 기반**으로 완성됨
- 따라서 당장 백엔드 연동이 필요하진 않으나, 백엔드를 함께 성장시켜 **추후 서버 저장 전환**을 대비함
- 현재 백엔드는 Spring Boot 초기 설정만 있고 **도메인 코드 전무**
- 이번 작업의 목표: 기반 구조 완성 + KanbanColumnConfig API + Company API 구현

- [ ] `Company` Entity 설계 (`model/company/domain/company/Company.kt`)

  - `name: String`
  - `applicationStatus: ApplicationStatus`
  - `memo: String?`
  - BaseEntity 상속
- [ ] `CompanyRepository` 인터페이스 (`model/company/domain/company/CompanyRepository.kt`)
  - `JpaRepository<Company, Long>` 상속

- [ ] `CompanyService` (`model/company/domain/company/CompanyService.kt`)
  - `getAll(): List<CompanyResponse>`

  - `updateStatus(id: Long, status: ApplicationStatus): CompanyResponse`

  - `CompanyResponse` (id, name, applicationStatus, memo, createdAt)
  - `CreateCompanyRequest` (name, applicationStatus, memo?) — `@Valid` 검증

- [ ] `CompanyController` (`model/company/api/controller/CompanyController.kt`)

## 프론트 연동 시 변경 포인트 (향후 작업)

> 현재 프론트는 localStorage 기반으로 동작 중. 추후 아래 항목을 연동하면 서버 동기화 가능

| 프론트 위치 | 현재 방식 | 전환 후 |
|-------------|-----------|---------|
| `useAppStore` companies | localStorage persist | `GET /api/companies` 조회 |
| Company CRUD | store 직접 조작 | REST API 호출 |
| `useAppStore` kanbanColumns | localStorage persist | `GET /api/kanban-columns` 조회 |
| KanbanColumnSettingModal 저장 | `setKanbanColumns` | `PUT /api/kanban-columns` 호출 |
| 칸반 드래그 상태 변경 | store 직접 조작 | `PATCH /api/companies/{id}/status` 호출 |
