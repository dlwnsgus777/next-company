## 1. 현재 구조 분석

### 문제점
`KanbanBoard.tsx`의 `COLUMNS` 배열이 하드코딩되어 있어 사용자가 컬럼 구성을 변경할 수 없음.

```typescript
// 현재: 코드에 고정된 5개 컬럼
const COLUMNS = [
  { key: 'not_applied', label: '지원 전',  statuses: ['NOT_APPLIED'] },
  { key: 'applied',     label: '서류 지원', statuses: ['APPLIED', 'DOCUMENT_PASS'] },
  { key: 'interview',   label: '면접 진행', statuses: ['FIRST_INTERVIEW', 'SECOND_INTERVIEW'] },
  { key: 'accepted',    label: '최종 합격', statuses: ['FINAL_ACCEPTED'] },
  { key: 'rejected',    label: '탈락',      statuses: ['REJECTED', 'WITHDRAWN'] },
]
```

### ApplicationStatus 목록 (변경 불가 고정값)
| 값 | 라벨 |
|----|------|
| NOT_APPLIED | 지원 전 |
| APPLIED | 서류 지원 |
| DOCUMENT_PASS | 서류 합격 |
| FIRST_INTERVIEW | 1차 면접 |
| SECOND_INTERVIEW | 2차 면접 |
| FINAL_ACCEPTED | 최종 합격 |
| REJECTED | 탈락 |
| WITHDRAWN | 지원 취소 |

## 2. 요구사항

### 커스터마이징 가능 항목
1. **컬럼 이름** 변경 — "지원 전" → "관심 목록" 등 자유 입력
2. **컬럼 색상** 변경 — 8가지 프리셋 색상 중 선택
3. **컬럼 추가 / 삭제** — 원하는 단계를 세분화하거나 통합
4. **컬럼 순서** 변경 — 드래그로 재배치
5. **ApplicationStatus 배치** — 각 상태를 원하는 컬럼에 자유롭게 배치

### 제약사항
- 컬럼은 최소 1개 이상 유지
- 모든 ApplicationStatus는 반드시 어느 한 컬럼에 배치되어야 함 (미배치 불가)
  - 미배치 상태가 있으면 저장 버튼 비활성화
- 컬럼 이름은 비어 있을 수 없음

export interface KanbanColumnConfig {
  id: string
  label: string
  statuses: ApplicationStatus[]   // 이 컬럼에 속한 상태들

## 7. 고려사항

### 컬럼 삭제 시 상태 재배치 처리
컬럼을 삭제하면 해당 컬럼에 배치된 ApplicationStatus들이 미배치 상태가 됨.
→ 삭제 즉시 해당 상태들을 모두 "미배치"로 이동, 사용자가 직접 재배치하도록 안내.
→ 미배치 상태가 있으면 저장 불가 → 사용자가 반드시 처리해야 함.

### 신규 컬럼 추가 시
빈 컬럼(statuses: [])으로 추가 → 사용자가 상태를 배치하기 전까지 저장 불가는 아님.
빈 컬럼은 허용 (카드가 0개인 컬럼 표시와 동일).

### localStorage 마이그레이션
기존 저장된 데이터에 `kanbanColumns`가 없을 경우 → `DEFAULT_KANBAN_COLUMNS`로 자동 폴백.
Zustand persist의 `version` 필드 활용 권장.
